# 로드맵

2D 원본([lazygyu/roulette](https://github.com/lazygyu/roulette))을 2.5D(물리는 2D, 렌더는 3D)로 옮기는 단계별 계획입니다. 각 단계는 끝났을 때 앱이 동작하는 상태를 유지하도록 나눴습니다.

0~5단계는 "원본과 같은 게임을 3D 로 그린다"가 목표였습니다. 6단계부터는 방향을 바꿔, 원본과의 기능 동등성을 내려놓고 3D 전용 추첨 게임으로 다시 짭니다. 원본과 같게 유지하는 것은 물리 시뮬레이션과 맵 데이터 형식뿐입니다.

## 결정 사항

| 항목        | 결정              | 이유                                                                                                    |
| ----------- | ----------------- | ------------------------------------------------------------------------------------------------------- |
| 물리        | 2D Box2D 유지     | 맵 데이터, 순위 계산, 카메라 로직이 모두 2D 좌표 기준이고, 물리 시뮬레이션을 원본과 같게 유지할 수 있다 |
| 3D 렌더링   | Three.js (바닐라) | 프레임워크 없는 TypeScript + DOM UI 구조다                                                              |
| 빌드        | Vite              | 원본의 `new URL(..., import.meta.url)` 에셋 방식이 그대로 동작한다                                      |
| 구슬 렌더링 | `InstancedMesh`   | 상한은 100개로 줄었지만 이미 만들어져 있고, 스킨을 없애면 구슬 전체가 인스턴스 하나로 정리된다          |

### 6단계부터 바뀌는 결정

| 항목      | 이전                                         | 이후                                                                     | 이유                                                                                                            |
| --------- | -------------------------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| 화면 구성 | 장면 캔버스 + 표시 캔버스 합성               | WebGL 캔버스 하나를 화면에 직접 둔다                                     | 합성 구조는 녹화가 표시 캔버스 하나만 찍기 때문에 있었고, 녹화를 없앤다                                         |
| HUD       | 2D 캔버스(`UIObject`)                        | HTML/CSS. 미니맵 안쪽 그림만 작은 캔버스                                 | 캔버스에 합성할 이유가 없어졌고, 글꼴·레이아웃·입력 처리가 DOM 쪽이 단순하다                                    |
| 렌더러    | 3D 기본, 2D 대체                             | 3D 하나. WebGL 을 못 쓰면 안내 문구만                                    | 2D 는 원본 화면과 대조하는 기준이었는데 그 목표를 내려놓는다                                                    |
| 테마      | 라이트·다크                                  | 다크 고정                                                                | 테마 분기가 사라지고 발광 재질이 항상 켜진다                                                                    |
| 당첨자    | 첫번째·마지막·N번째·여러 명                  | 항상 1등                                                                 | 결과 화면이 전체 순위표라 따로 고를 필요가 없다                                                                 |
| 게임 종료 | 당첨자 확정 시                               | 1등 확정 후에도 전원 골인까지 진행                                       | 최종 순위표를 채운다                                                                                            |
| 구슬 수   | 1,000개 규모                                 | 총 100개(`이름*N` 을 펼친 합계)                                          | 이름 라벨을 HTML 로 옮기는 전제다                                                                               |
| UI 코드   | `index.html` 인라인 스크립트 + `window` 전역 | TypeScript 모듈 + 화면 상태 머신                                         | 타입 검사와 린트가 UI 코드까지 닿는다                                                                           |
| 회귀 기준 | 추첨 결과와 2D 화면이 원본과 같다            | 물리 시뮬레이션(`simulate`)이 원본과 같다                                | 스킬·가중치를 없애면 게임 안의 결과는 원본과 달라진다. `simulate` 는 원래 스킬 없이 돌므로 기준값은 그대로 쓴다 |
| 디자인    | 원본 스타일                                  | 네온 아케이드. 제목은 굵은 글꼴(Black Han Sans), 본문은 고딕(Pretendard) | 다크 고정·블룸 화면과 맞춘다. 글꼴은 OFL 이고 npm 패키지로 번들에 넣는다                                        |

## 1단계: 스캐폴딩

원본을 새 빌드 환경으로 옮기고, 2D 상태 그대로 동작하는 것을 확인합니다.

- [x] Vite + TypeScript + Biome 구성 (`experimentalDecorators` 포함)
- [x] 원본 `src/`, `assets/`, `index.html` 복사, 원본 MIT 저작권 고지 포함
- [x] 프로젝트 이름·타이틀·manifest 를 원본 상표와 다른 이름으로 교체
- [x] 원작자 인프라 연결 제거: 분석 스크립트, 광고, 키워드 스프라이트, 맵 공유마당, 공지·샵 링크, 서비스워커 스크립트
- [x] `simulate` 스크립트 이식, 원본과 출력이 일치하는지 확인
- [x] Vitest 구성, 원본 골인 시각을 기준값으로 하는 회귀 테스트

완료 기준: 개발 서버에서 원본과 같은 2D 게임이 동작하고, `simulate` 출력이 원본과 같다.

## 2단계: 렌더 경계 분리

화면은 2D 그대로 두고, 3D 렌더러를 끼울 자리를 만듭니다.

- [x] `RouletteRenderer` 를 월드 그리기(엔티티, 구슬, 이펙트)와 HUD 그리기(순위표, 미니맵, 당첨자 표시)로 분리
- [x] 월드 렌더러 인터페이스 정의 (`WorldRenderer`, `WorldFrame`)
- [x] `Marble` 에서 그리기 코드 분리 (상태와 표현 나누기)
- [x] `GameObject.render(ctx, ...)` 처럼 2D 컨텍스트를 직접 받는 이펙트 인터페이스 정리
- [x] `Camera` 에서 캔버스 변환(`renderScene`)을 떼어내고 `(x, y, zoom)` 계산만 남기기
- [x] 분리 전 코드의 캔버스 호출 기록을 기준값으로 하는 회귀 테스트

완료 기준: 화면과 동작이 1단계와 같고, 월드 렌더러를 다른 구현으로 바꿔 끼울 수 있다.

## 3단계: 3D 월드 렌더러

- [x] Three.js 장면·렌더러 구성, WebGL 결과를 2D 장면 캔버스에 합성
- [x] 좌표 변환 계층 (물리 y 아래 방향 → Three.js y 위 방향)
- [x] 엔티티 메시 생성: `box` → 박스, `circle` → 원기둥 핀, `polyline` → 두께 있는 벽
- [x] 구슬 `InstancedMesh`, 위치·회전 동기화
- [x] 카메라 어댑터: `(x, y, zoom)` → 원근 카메라 위치·거리
- [x] 맵 전환 시 메시 생성·해제
- [x] `?renderer=2d` 및 WebGL 실패 시 2D 렌더러로 대체

완료 기준: 기본 맵 전체에서 구슬이 3D 로 굴러 골인하고, HUD 가 그 위에 정상 표시된다.

## 4단계: 기능 동등성

원본의 기능 중 3단계에서 빠진 것을 채웁니다.

- [x] `kinematic` 회전 구조물, `life` 가 있는 부서지는 구조물 (3단계에서 메시 동기화에 포함)
- [x] 구슬 이름 표시, 스킨 이미지, 당첨 구슬 강조
- [x] 스킬 이펙트와 쿨타임 표시
- [x] 미니맵 (구슬·뷰포트 표시, 마우스를 올린 위치로 카메라 이동)
- [x] 라이트·다크 테마
- [x] 화면 녹화 (표시 캔버스 스트림에 3D 화면이 담기는 것 확인)
- [x] 디버그 표시 (진행도 지도, 연출 구역, 카메라 구역)
- [x] 외부 맵(`StageDef` JSON) 파일 불러오기. 형태 검증은 원본 `communityMaps.ts` 의 `isPlayableStage` 를 가져왔다

완료 기준: 원본에서 되던 플레이 흐름이 모두 3D 화면에서 된다.

## 6단계: 기능 제거

새 UI 를 올리기 전에 걷어낼 것을 먼저 걷어냅니다. 이 단계에서는 원본 구조의 설정 패널과 캔버스 HUD 가 그대로 남아 동작합니다.

- [x] 스킬: 충격파 판정, `SkillEffect`, `EffectMeshes`, 쿨타임 호, 토글, `IPhysics.impact`, 번역 키
- [x] 녹화: `VideoRecorder`, 옵션과 토글, 시작·종료 호출
- [x] 라이트 테마: 토글, `Themes.light`, 3D 렌더러의 테마 분기 (발광과 블룸은 항상 켠다)
- [x] 가중치: `이름/3` 문법, 중복 합치기의 가중치 키. `이름*N` 은 유지
- [x] 당첨 순위 설정: 모드 버튼, 당첨 범위(`WinnerRange`), 당첨자 패널, 여러 명 결과 팝업과 `closeButton`. 당첨자는 1등으로 고정
- [x] 구슬 스킨: `marbleSkins`, 스킨 이미지, 스킨용 개별 메시와 UV
- [x] 맵 파일 불러오기: 업로드 버튼, `stageFile.ts` 와 그 테스트
- [x] `?names=` 주소 파라미터
- [x] 2D 렌더러: `Canvas2dWorldRenderer`, `?renderer=2d`, 화면 파티클(`ParticleManager`, `Particle`), `rendersAtDisplayResolution` / `drawsGoalBursts` 플래그
- [x] WebGL 을 못 쓰는 환경에서는 안내 문구만 표시
- [x] 구슬 총합 100개 상한 (`setMarbles` 에서 넘는 입력을 받지 않는다)
- [x] 테스트 정리: `worldRender`, `effectMeshes`, `stageFile` 테스트와 2D 호출 기록 기준값 삭제. `simulate` 회귀 테스트는 유지 (`recordingContext` 는 `marbleOverlay` 테스트가 쓰고 있어 7단계에서 함께 지운다)
- [x] CLAUDE.md, README 갱신: "2D 가 원본 화면의 기준", "추첨 결과가 원본과 같아야 한다"를 "물리 시뮬레이션이 원본과 같다"로 줄인다

완료 기준: 3D 화면에서 이름 입력 → 시작 → 1등 확정까지 동작하고, `simulate` 기준값을 고치지 않은 채 테스트·타입 검사·린트가 통과한다.

## 7단계: 캔버스 하나와 HTML HUD

- [x] WebGL 캔버스를 화면에 직접 붙이고 장면·표시 캔버스 이중 구조, `sizeFactor`, 마우스 좌표 변환을 없앤다
- [x] `WorldRenderer` 인터페이스를 접는다. 구현이 하나라 `ThreeWorldRenderer` 가 `WorldFrame` 을 직접 받는다
- [x] HUD 층: 캔버스 위에 겹친 HTML 루트. `Roulette` 은 DOM 을 모르고 프레임마다 읽기 전용 상태(순위, 구슬 화면 좌표, 골인 이벤트)를 내놓고, HUD 모듈이 그것을 읽는다
- [x] 디자인 토큰(색, 발광 테두리, 간격)과 글꼴 번들. 외부 CDN 을 쓰지 않는다
- [x] 랭킹 보드: 순서나 골인 상태가 바뀐 행만 DOM 을 고친다
- [x] 배속 버튼 (캔버스를 누르고 있는 방식 대신 켜고 끄는 버튼)
- [x] Winner 표시, 도착 알림
- [x] 미니맵: 틀은 HTML, 맵·구슬·뷰포트는 작은 캔버스. 마우스를 올린 위치로 카메라 이동은 DOM 이벤트로 다시 잇는다
- [x] 구슬 이름 라벨: 구슬마다 HTML 요소를 재사용하고 `transform` 만 프레임마다 갱신한다. 투영 계산은 `marbleOverlay` 의 것을 순수 함수로 남겨 단위 테스트한다
- [x] 선두 구슬 강조는 라벨 스타일로 (당첨 테두리 대체)
- [x] `UIObject`, `RankRenderer`, 캔버스판 `Minimap`·`FastForwader`, `drawMarbleOverlay` 삭제 (테스트 도우미 `recordingContext` 포함)
- [x] 디버그 표시(`DebugPlane`)는 3D 장면 안의 텍스처라 그대로 둔다

완료 기준: 화면에 캔버스가 하나뿐이고, HUD 가 창 크기와 무관하게 선명하며, 구슬 100개에서 라벨 갱신이 프레임을 떨어뜨리지 않는다.

## 8단계: UI 모듈과 화면 흐름

```
로비 ──(다음)──▶ 맵 선택 ──(선택)──▶ 게임 화면 ──(시작)──▶ 진행 ──▶ 결과
                              ◀──(맵 선택으로)──        [다시 하기] [로비로]
```

- [x] `index.html` 인라인 스크립트를 `src/ui/` 모듈로 옮기고 `window.roulette` / `window.options` 전역을 없앤다
- [x] 화면 상태 머신(로비, 맵 선택, 게임, 진행, 결과). 프레임워크 없이 상태마다 진입·이탈 함수를 둔다
- [x] 번역: 새 UI 기준으로 키를 다시 만들고 타입으로 누락을 잡는다. 한국어·영어, 브라우저 언어로 고른다
- [x] 로비 입력: 엔터 한 번에 이름 하나, 붙여넣은 쉼표·줄바꿈 구분 이름은 한 번에 처리, `이름*N` 유지, 같은 이름은 개수로 합친다
- [x] 로비 목록: 칩으로 보여주고 칩을 누르면 지운다. 총합 100개를 넘는 입력은 받지 않고 안내한다
- [x] 이름 저장: localStorage. 키는 새 접두사로 만들고 원본의 `mbr_names` 는 읽지 않는다
- [x] 맵 선택: 전체화면 세로 카드, 맵 이름과 길이(`goalY`). 썸네일은 맵 데이터로 런타임에 2D 캔버스에 그린다. 데스크톱 기준
- [x] 게임 화면: 맵을 가리지 않는 자리에 섞기·시작 버튼, 맵 선택으로 돌아가기
- [x] 진행 규칙 변경: 1등이 확정돼도 멈추지 않고 전원 골인(또는 구슬이 하나 남을 때)까지 진행한다
- [x] 줌인·슬로모션 연출은 1등이 결정될 때까지만 건다. 첫 골인 뒤에는 줌과 `timeScale` 을 기본값으로 두고 카메라는 남은 선두를 따라간다
- [x] 결과 연출: 1등 확정 시 랭킹이 화면 중앙으로 커진다. 골인 전인 행은 반투명에 현재 진행 순위대로 움직이고, 결승선을 통과하면 불투명해지며 자리가 고정된다
- [x] 결과 버튼: 1등 확정 직후부터 [다시 하기] [로비로] 를 누를 수 있다. 다시 하기는 맵과 이름을 유지한 채 게임 화면으로, 로비로는 로비로 간다
- [x] 좁은 화면에서 레이아웃이 깨지지 않는지 확인 (모바일 전용 배치는 만들지 않는다). 폭 375px 에뮬레이션으로 로비·맵 선택·게임 화면을 확인했고, 실제 터치 기기 확인은 11단계로 넘긴다

완료 기준: 로비에서 결과까지, 결과에서 두 갈래로 되돌아가는 흐름이 새 UI 만으로 돌고, `index.html` 에 인라인 스크립트가 없다.

## 9단계: 로비 구슬 박스

- [x] 로비 전용 물리 월드. 게임 월드와 별도 인스턴스이고, 박스는 목록에 나오지 않는 내부 `StageDef` 로 만들어 `StageMeshes`·`MarbleMeshes` 를 그대로 쓴다
- [x] 이름을 추가하면 구슬이 생겨 박스로 떨어진다. `이름*N` 은 N 개가 떨어진다
- [x] 칩을 지우면 해당 구슬이 사라지는 효과와 함께 빠진다
- [x] 저장된 이름으로 로비에 들어오면 구슬이 한꺼번에 쏟아진다
- [x] 로비를 떠날 때 로비 월드를 정리하고, 게임은 원래 출발 배치로 구슬을 새로 만든다 (로비 상태가 추첨에 섞이지 않는다)

완료 기준: 로비에서 구슬을 넣고 빼는 것이 게임 시작 배치와 `simulate` 결과에 영향을 주지 않는다.

## 10단계: 맵 시각 개선과 카메라 시점

- [x] 맵 안팎 마스크: `ProgressMap` 에서 결승선과 이어진 칸을 뽑는 순수 함수. 칸이 0.25 단위라 텍스처로 쓸 때 경계를 부드럽게 한다
- [x] 안쪽 바닥 텍스처, 바깥은 어둡게 하거나 안개
- [x] 맵 선택 썸네일에 같은 마스크 적용
- [x] ~~환경설정 버튼과 패널~~ → 없앴다. 카메라 각도는 게임 화면을 끌어서 바꾸고 localStorage 에 저장한다. 게임 중에도 바로 반영된다
- [x] 화면을 위아래로 끌면 기울기(−30° ~ 30°, 기본 17°), 좌우로 끌면 옆으로 도는 각도(−30° ~ 30°, 기본 0°). 두 번 누르면 기본값
- [x] ~~그림자 끄기, 블룸 끄기~~ → 끄는 설정 없이 항상 켠다. 저사양 대응은 11단계에서 성능을 재고 정한다
- [x] 결승 연출: 좌우 흔들림은 사용자가 고른 좌우 각도를 중심으로 한다
- [x] 휠·트랙패드 핀치·두 손가락 핀치로 배율(0.5 ~ 2.5배). 결승 연출이 깊어질수록 1배로 돌아간다. 두 번 누르면 각도와 함께 기본값
- [x] 로비의 구슬 박스도 끌고 굴려서 시점을 바꾼다 (게임과 같은 시점을 같이 쓴다)
- [x] 결승 연출 기울기: 더 기우는 각도를 기본 기울기에 비례시킨다(지금 비율 유지, 기울기 0 이면 추가 기울기도 0, 음수면 반대로). 합계는 ±60도로 제한
- [x] 미니맵 뷰포트 보정: 화면 네 모서리를 z = 0 평면에 투영한 사각형으로 그린다. 그림자 범위(`followView`)도 같은 사각형을 덮게 한다 (카메라가 맵 위쪽에서 내려다보므로 화면 아래쪽이 넓은 사다리꼴이다)
- [x] 시작 전에 미니맵으로 다른 곳을 봤다가 마우스를 떼면 카메라가 원래 자리로 돌아오게 고침

완료 기준: 기울기 양 끝(−30, 30)에서 미니맵 표시가 실제 화면 범위와 맞고 그림자가 잘리지 않는다.
